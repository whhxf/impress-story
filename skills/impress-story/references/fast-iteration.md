# 快速修改与即时预览

## 先修流程，不先优化引擎

本次作品的构建和必要检查原本仅0.06–0.09秒。分钟级等待主要来自反复读取资料、逐次浏览器启动与截图、过度回归、字体子集联网补字、手动刷新和重复打包。不要把这些归咎于impress.js。

每轮先判断变更范围，不把所有修改升级为制作任务：

| 修改 | 默认动作 | 不做 |
| --- | --- | --- |
| 明确文案、标题、备注 | 一次修改JSON，自动构建/检查/刷新 | 不重新规划，不开浏览器，不截图，不读整套资料 |
| 替换用户现成截图 | 复制素材，改引用，检查文件存在 | 不重新抓站、不生图、不默认看图 |
| 箭头、形状、构图、布局 | 改对应几何，检查受影响对象，按需预览该页 | 不顺带检查全部演示与手机 |
| 动效、导航、空间结构 | 检查相关路径、减少动态效果与必要尺寸 | 不对无关文字反复润色 |
| 真正的生图、抠图、风格重绘 | 按imagegen能力制作并看结果 | 不承诺像文案替换一样即时完成 |

清楚的请求直接执行。只读需要定位的场景；上下文已经给出稳定ID时，不再通读全稿。沿用用户确认过的规则和素材，不重开风格讨论。

## 一次准备字库

本Skill自带 assets/fonts/LXGWWenKaiTC-Regular.ttf、OFL-LXGWWenKaiTC.txt、source.json。新作品复制完整字体与许可到作品assets，建立本地@font-face；source.json记录来源、摘要、字形覆盖与许可。不要把仅含当前几百字的接口结果作为正文唯一字库。

正文已经包含常用简繁中文与Latin，不等于涵盖所有Unicode字符。用scripts/font_coverage.py对实际使用文件检查；不能把未加载的备份字体合并算覆盖率。少见字缺失时先使用已获许可的本地完整备选字体，不能在每次普通改字时联网取子集。

只为解决实际动效瓶颈，才建立小字库/位图缓存。缓存不影响正文编辑；其文字变化时从本地完整字库处理，不能重新启动远程下载工作流。

## 一次开预览，后续保存即刷新

已有规则项目使用：

```sh
python3 '<skill>/scripts/preview.py' --project '<project>' --port 8767
```

服务只绑定127.0.0.1。保持进程运行，首次在Codex预览打开一次；之后不逐次打开新URL或新浏览器任务。项目根目录.preview-state.json记录地址、PID、存活时间、最后构建耗时与错误，不进交付包。恢复工作时先检查该状态，已有活服务就复用。端口被其他项目使用时选择别的端口，不杀无关进程。

服务监听content/*.json、build.py、verify.py、styles.css、presentation.js、素材。忽略index.html等生成物和review，避免自身触发循环。build.py和verify.py存在时运行它们；有Node时检查presentation.js语法。全部通过后才发布统一快照，错误时保留上一版。浏览器自动重载并保留当前hash、讲稿面板、阅读模式/位置；失误不会把坏版推到观众面前。

刷新脚本只由预览服务注入，不写进导出的index.html，双击HTML及正式交付不依赖预览服务。

## 单处或批量文案，一次构建

```sh
python3 '<skill>/scripts/edit_scene.py' --project '<project>' --scene early --title 'Conan 亲身经历' --subtitle '面对面聊客户，找体感'
```

也支持 --notes、--labels（JSON数组）、--asset、重复 --set FIELD=JSON。一次把相关字段写完，避免逐字段反复构建。工具原子写入content/scenes.json，发现活预览服务就等待它验证，绝不再并行构建一遍；没服务时只执行一次构建与检查。返回validated、耗时和同一个预览地址。

多页反馈不要逐页启动命令。将本批修改保存为临时 JSON，一次执行：

```json
[
  {"scene":"early","changes":{"title":"客户愿意付钱，就值得继续做。","subtitle":""}},
  {"scene":"test","changes":{"notes":"改完后先测，再发布。"}}
]
```

```sh
python3 '<skill>/scripts/edit_scene.py' --project '<project>' --batch '<edits.json>'
```

所有目标和字段先在内存校验，再原子写一次。任一目标不存在、字段类型错误或标题过长，不写入任何场景。构建失败时已有预览保留上一份可用快照；内容源保留本次修改以便修复，不声称已回滚文件。成功只说明项目构建/检查通过，不代表完成视觉验收。没有构建或验证入口时先配置，不返回虚假的 validated。

定位时可只读候选页：

```sh
python3 '<skill>/scripts/edit_scene.py' --project '<project>' --page 11 --prefer-next --query '早期采购'
```

--prefer-next只用于用户明确说明页码落后一页的情况，不对所有用户强套。查明后以稳定ID修改。查询不唯一就缩小范围，不猜场景。

标题变更同时处理旧screenTitle；当前两行标题区域采用保守换行，过长则要求简化或调整版式，不默默缩小所有字。此保护不等于精确投影验收。封面/结尾/章节若有专用绘制逻辑，先确认其显示文字也来自数据；新作品不要把可编辑文案硬编码到绘图函数。

## 新作品不重写播放器

`scripts/init_project.py --project '<new-project>'` 初始化可运行的手绘底座，先建立AGENTS规则，只接受空目录。自带本地impress.js、字体和许可；无网络依赖。生成的build.py从scenes.json读取标题、备注和自由SVG art；坐标、标题位置与字号可以按场景调整。示意内容要替换，不能当作用户稿件；原始素材不得以项目示例进入共享Skill。

自由SVG中的文本同样属于内容。修改该文本时直接改art，避免只改title却留着画面里的旧字；edit_scene的自动换行只保护标准标题，不处理art。现有项目优先原地适配，不运行初始化器覆盖它。

## 保持又快又好

- 修改前做一次内部“人话检查”：谁遇到什么、怎么做、为什么。明确替换不擅自扩写。
- 先保存，交给自动检查发布；别在已经通过后继续扩大测试。
- 仅影响连接器端点附近文字时做局部边界检查；其他标题改字不触发全图箭头审计。
- 平时不打包、不部署、不推送。用户需要交付包时再生成一次。
- 不为每次小改更新长篇日志。内容真源与必要来源要维护；过程批次结束后再简短记录。
- 快改回复直接说改了什么。普通文案不再列一长串验证清单。

## 验证与速度口径

运行 scripts/test_fast_iteration.py 做定向测试。实际预览首次接入时，验证文字自动更新、当前位置保留、坏内容不发布及恢复；不要每次改字重跑这些系统测试。

已验证案例在本机保存到画面更新约0.43–0.70秒，包含构建和刷新；不包含理解自然语言、模型推理、工具启动或图像生成。应测实际时间，不承诺所有请求一秒完成。


## 测量真正的瓶颈

区分三段：理解与设计时间、源文件到可用预览的时间、浏览器实际绘制/转场时间。单看build_ms不能代表整条流程。只在流程或工具变更时测相关项，不为每次改字跑性能报告。

先用功能等价的同一条件比较：是否相同字库、相同场景、相同验证范围。批量编辑关注构建次数和坏批次是否零写入；初始化关注无网络可运行和不覆盖旧作品。自动化失败要停在上一份可用预览，不以跳过验证缩短数字。
