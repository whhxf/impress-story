# Impress Story

**把你不断补充的讲稿、图片和视频，做成手绘白板风格的空间演示。**

你用自然语言讲内容、提修改意见；AI 负责整理故事、设计图形关系、安排镜头，并生成可运行的 impress.js HTML。适合喜欢 Prezi 式缩放叙事，又不想手动排列坐标的人。

[![Impress Story 手绘空间演示首屏：AI 外贸员，是怎么长出来的？](docs/demo-cover.webp)](https://agent.ksway.net/resources/talks/ai-sales-agent/#/cover)

[查看实际演示效果](https://agent.ksway.net/resources/talks/ai-sales-agent/#/cover) · [Skill 入口](skills/impress-story/SKILL.md) · [空间叙事规则](skills/impress-story/references/spatial-story.md)

> 在线链接是用这套方法制作并迭代的实际作品，不是初始化器一键生成的成品。每份演示的内容与构图仍需 AI 根据讲稿设计，并通过实际预览打磨。本项目不隶属于 Prezi。

## 可以做出什么效果

| 效果 | 展示方式 | 实现边界 |
| --- | --- | --- |
| 从全局进入细节 | 一张关系地图，放大到局部，缩小回到全局，再进入另一部分 | impress.js 镜头能力；空间布局按内容制作 |
| 连续的手绘白板 | 规整手写字体、纸色背景、线条、圈注、图形与图片结合 | 有意设计线条和构图，不靠随机抖动制造潦草 |
| 先画线，再揭示 | 箭头逐渐画出，随后出现解释文字 | SVG/CSS 补充动画；不是真实汉字逐笔书写引擎 |
| 平移、缩放和三维旋转 | 根据内容关系切换视角 | 引擎具备能力；不是每个场景都默认旋转，需注意眩晕与性能 |
| 图片与影片辅助讲述 | 整合用户素材，放大、聚焦或安排播放 | 放大查看、视频控件和离场暂停等需按作品接入和验证 |
| 演讲与阅读两种方式 | 键盘翻页、讲稿备注、地图返回、手机阅读 | 基础底座已提供；支持减少动态效果偏好 |

**重点是让听众看懂关系、记住转折。** 不把每段稿子塞进同一种卡片，也不靠不停运动制造“高级感”。

## 适用范围

适合：

- 产品介绍、开发经验分享、案例复盘和团队培训。
- 需要解释因果、取舍、流程、层级或系统关系的讲述。
- 先有零散台词，想边讲边整理、边看边改的制作方式。
- 想得到本地可编辑 HTML，或后续自行部署到静态托管平台。

不适合直接当作：

- Prezi 的拖拽编辑器、多人在线协作平台。
- 一句话自动生成且无需打磨的成品幻灯片工具。
- 原生 PPTX/PDF/视频导出器或完整三维建模工具。
- 自动补造数据、客户证言和个人经历的内容生成器。

## 安装

通过支持 Agent Skills 的安装器安装：

```bash
npx -y skills add whhxf/impress-story -g --all
```

需要 Node.js/npm；安装前可先查看仓库中的脚本。安装器会根据目标 Agent 设置安装位置。重启或刷新 Agent 后，确认能发现 `impress-story`。

也可下载仓库，将整个 `skills/impress-story/` 文件夹放入目标工具的 Skills 目录。**不能只复制 SKILL.md**：字体、许可、运行时、脚本和参考文档都需要保留。不同工具的目录约定不同，以目标工具说明为准。

## 最简单的用法

在已安装 Skill 的 AI 工具中输入：

```text
使用 impress-story，帮我做一份手绘白板风格的空间演示。
观众是刚入职的同事，目标是让他们理解产品解决什么问题。
我会逐段提供讲稿。先记录，等我说“开始制作”再生成。
```

继续提供内容、图片和视频。开始制作时，例如：

```text
开始制作。不要套固定卡片模板。
先给我一张总览地图，再进入各个部分。
关键的选择要讲清原因，屏幕少放字，讲稿保留完整解释。
```

迭代时直接说：

```text
把“产品能力边界”改成“哪些事还得人来做”。
这两页其实是同一个问题，放到一张图里，先看左边，再回全局看右边。
红色回线用1.5秒画出来，再出现下面的文字。
这张截图换成我刚发的图片，其余不动。
```

你不需要提供坐标、SVG 路径或缩放参数。AI 应根据内容处理，遇到真正阻碍执行的信息才询问。

## 从讲稿到作品

```text
原话与素材 → 核心信息与故事 → 可信检查与演讲稿
          → 关键画面与空间关系 → HTML预览 → 按反馈局部打磨
```

- 原话保留；屏幕短句与口述备注分别组织，不把缩句当成写好讲稿。
- 文案用具体的人、事、动作和原因说清楚，避免一串抽象结论。
- 真实的情境、问题、选择和反馈构成推进；不为了煽情编故事。
- E-E-A-T 只启发来源与可信度检查，不是 Google 对演示的认证或评分。
- 放大表示进入细节，缩小用来揭示关系；没有信息用途的动画应删去。

## 为什么迭代更快

按“质疑要求 → 删除多余 → 简化 → 缩短周期 → 最后自动化”的顺序改进流程：

- **新作品复用底座**：播放器、完整字体和运行时本地就绪，不反复搭环境。
- **多处修改一次提交**：按稳定场景 ID 批量编辑，只构建一次。
- **保存后自动刷新**：预览保留当前场景、讲稿面板与阅读位置。
- **检查按影响范围执行**：改字不截图、不重跑整套浏览器验收；布局和交互做局部实际检查。
- **失败保留可用预览**：坏构建不会替换上一份通过检查的预览。源文件保留本次修改，便于修复。

这能减少重复劳动，但不承诺完整制作只需几秒。理解内容、原创构图、生图、复杂动效和实际演练仍需要时间。

## 环境依赖

| 环节 | 所需环境 |
| --- | --- |
| 理解讲稿、选择图形、修改代码 | 支持 Skills、文件编辑和命令执行的 AI Agent |
| 初始化、构建、编辑、预览、字形检查 | Python 3；工具仅使用标准库。当前测试环境为 Python 3.14 |
| 安装命令 | Node.js/npm；仅手动复制安装则不需要 |
| JavaScript 语法检查 | Node.js，存在时预览服务会使用 |
| 实际展示与交互检查 | 现代桌面或移动浏览器；Agent 自动检查需其可用的浏览器工具 |
| 搜图、生图、抠图等扩展 | 按需使用目标环境的工具，可能需要网络、额外权限或费用 |

基础工具和完整字体随仓库提供，初始化不需要下载 CDN 依赖。当前开发环境使用 ego-browser；其他环境可使用用户允许的等效工具。没有浏览器条件时不能声称已完成交互验证。

## 手动启动与维护

以下命令从仓库根目录执行，或让 AI 按实际安装路径替换前缀：

```bash
# 新项目必须不存在或为空；不会覆盖已有作品
python3 skills/impress-story/scripts/init_project.py --project ./my-talk

# 本机预览。保持此进程运行，修改源文件后自动构建并刷新
python3 my-talk/preview.py --project ./my-talk --port 8767
```

打开 `http://127.0.0.1:8767/`。启动内容只是示意，需要用正式内容替换。

单处修改：

```bash
python3 my-talk/edit_scene.py --project ./my-talk \
  --scene question --title '为什么要重新做一遍？' --subtitle ''
```

多处修改先保存为 `edits.json`：

```json
[
  {"scene":"question","changes":{"title":"问题出在哪里？","subtitle":""}},
  {"scene":"choice","changes":{"notes":"先说明当时的选择，再讲反馈。"}}
]
```

```bash
python3 my-talk/edit_scene.py --project ./my-talk --batch ./edits.json
```

批次先校验再原子写入；目标不存在或字段类型错误，不写入任何场景。命令中的标题修改不负责改写自由 SVG `art` 内另行编写的标签；AI 应同步修改受影响画面，避免两份文案漂移。

## 文件结构

```text
skills/impress-story/
├── SKILL.md                 # 行为与流程入口
├── agents/openai.yaml       # Codex 界面元数据
├── references/              # 讲稿、人话、空间叙事、连接器与验收规则
├── scripts/
│   ├── init_project.py      # 免联网创建可运行底座
│   ├── edit_scene.py        # 单处/批量修改
│   ├── preview.py           # 验证后自动刷新
│   ├── font_coverage.py     # 实际字形覆盖检查
│   ├── audit-connectors.js  # 浏览器连接器专项检查
│   └── test_fast_iteration.py
└── assets/
    ├── starter/             # 通用构建、验证与播放器，不限定页面构图
    ├── runtime/             # 固定的 impress.js 及 MIT 许可
    └── fonts/               # LXGW WenKai TC、OFL许可与来源
```

生成的项目保留 `content/` 内容源、`assets/` 原素材、`vendor/` 运行时和 `review/` 必要记录。正式 HTML 与讲稿由构建产生。默认不部署、不上传素材，也不自动推送 Git。

## 验证与已知边界

```bash
python3 skills/impress-story/scripts/test_fast_iteration.py
```

当前包含 14 项定向测试：批量只构建一次、错误批次零写入、初始化不覆盖旧项目、坏预览保留与恢复、字体覆盖等。基础底座还做过桌面键盘、讲稿、地图返回、减少动态效果、390px 手机阅读的浏览器检查。

这些检查不证明所有新作品都达到同样效果。新作品仍需验证实际布局、文字、媒体、转场与演讲节奏。复杂箭头可能需要调整通道和端口；自动包围盒与路径采样不能代替实际查看。离线播放、视频兼容性和目标设备表现，应按交付条件单独验证。

运行时按文件摘要固定，具体来源和版本说明见 [runtime/source.json](skills/impress-story/assets/runtime/source.json)，不只凭历史文件名推断上游版本。
